# Telling Kong about your app.

That's it. Nothing else.

Kong is installed. Your app is running. But right now **Kong has no idea your app exists.** Kong is just sitting there an empty gateway, pointing to nothing.

So you need to say:

> *"Hey Kong, there's an app at `127.0.0.1:3000`, listen on `/api`, and protect it with these rules."*

Those 3 ways are just **3 different methods to give Kong that information.**

```
Way 1 → curl commands      ──┐
Way 2 → YAML file          ──┼──► All do the SAME thing. Just different styles.
Way 3 → Click in UI        ──┘
```

---

## The Big Picture — What You're Actually Building

**Right now your world looks like this:**

```
Someone          Your App
  │    ────────►   (Docker / kube / etc :3000)
  │    direct
  │    NO protection
  │    NO rate limit
  │    NO auth
```

**After you configure Kong, it looks like this:**

```
Someone          Kong                    Your App
  │    ────────► (bare metal :8000)  ────────►  (Docker :3000)
                      │
                      ├─ Is this person allowed?   (auth)
                      ├─ Are they spamming?         (rate limit)
                      ├─ Where should I send this?  (routing)
                      └─ Log everything             (observability)
```

Kong sits in the middle. **Your app never talks to the outside world directly anymore.**

> **Port 8000** → where users/Postman hit Kong (the proxy)

> **Port 8001** → where YOU talk to Kong to configure it (the admin API)

---

## What You Need to Create in Kong and WHY

There are **4 things** to create, in this exact order:

```
1. Service     "Here is my backend app"
2. Route       "Here is the URL Kong should listen on"
3. Plugins     "Here are the rules / protection"
4. Consumer    "Here is WHO is allowed to call it"
```

---

### 1. Service Register Your Node App with Kong

**What it is:** You're telling Kong *"there's a backend app living at this address."*

**Why it exists:** Kong needs to know WHERE to forward requests. Without a Service, Kong has nowhere to send traffic.

```
Kong Admin (port 8001)  you talk here to configure Kong
Kong Proxy (port 8000)  your users / Postman hit this

Service = your app's address, stored inside Kong's PostgreSQL database
```

---

### 2. Route Tell Kong Which URLs to Listen On

**What it is:** The rule that says *"when a request comes in at `/api`, send it to the xyz-app Service."*

**Why it exists:** Kong can manage MANY apps at once. Routes are how Kong knows which request goes to which app.

```
/api      → nodejs-app        (your app)
/payments → payment-service   (some other future app)
/auth     → auth-service      (some other future app)

All coming in on port 8000 — Kong routes them correctly.
```

---

### 3. Plugins Add Protection & Features

**What it is:** Rules you attach to a Service or Route. Kong runs these on **every request** before forwarding it.

**Why it exists:** So your Node app doesn't have to write auth code, rate limit code, or logging code Kong handles all of it.

```
Request comes in on port 8000
        │
        ▼
  [key-auth plugin]       [ Valid API key? No → 401 Unauthorized. STOP ]
        │
        ▼
  [rate-limiting plugin]  [ Too many requests? → 429 Too Many Requests. STOP ]
        │
        ▼
  Your App                [ Finally reaches here — clean and verified ]
```

Your app only ever sees **legitimate, authenticated, non-spammy** requests. It does zero security work itself.

---

### 4. Consumer The Identity of Who's Calling

**What it is:** A name + an API key. Represents *who* is calling your API.

**Why it exists:** So Kong can track, limit, and allow/block specific callers individually.

```
Consumer "postman-rahul"    → key: abc123   → you, testing from Postman
Consumer "mobile-app"       → key: xyz789   → your frontend / mobile app (future)
Consumer "partner-company"  → key: def456   → some external caller (future)
```

- Each gets their **own** rate limit bucket
- Each can be blocked **independently** without affecting others
- Your Node app knows **WHO called it** via headers Kong automatically injects:
  - `X-Consumer-Username: postman-rahul`
  - `X-Consumer-Custom-Id: dev-001`
  - `X-Forwarded-For: <real client IP>`

---

## Quick Mental Model — Remember This Forever

| Kong Concept | What It Actually Is |
|---|---|
| **Service** | Your backend app's address stored in Kong |
| **Route** | The URL pattern Kong listens on |
| **Plugin** | A rule/feature that runs on every request |
| **Consumer** | An identity (app/client) with an API key |
| **Port 8000** | Where the world talks to Kong |
| **Port 8001** | Where you configure Kong |
