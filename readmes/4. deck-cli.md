## deck: Declarative configuration for Kong

[![asciicast](https://asciinema.org/a/238318.svg)](https://asciinema.org/a/238318)

## What is decK?

decK is a **CLI (Command Line Interface) tool** used to manage Kong configuration.

Think of it like:

| Tool | Purpose |
|------|----------|
| Terraform | Manage infrastructure |
| kubectl | Manage Kubernetes |
| decK | Manage Kong |

decK allows you to:

- Export Kong configuration
- Store configuration in YAML files
- Compare changes
- Sync configuration automatically
- Detect configuration drift
- Automate Kong configuration in CI/CD pipelines

---

## What is Declarative Configuration?

Declarative configuration means:

> You describe the final desired state.

Instead of writing step-by-step commands.

Example:

```yaml
services:
  - name: payment-service
    url: http://payment-api
```

This tells decK:

> "Kong should contain this service."

decK then figures out whether it needs to:

- create it
- update it
- leave it unchanged

---

## How decK Works

### Step 1: Export Existing Kong Configuration

```bash
deck dump
```

This exports Kong configuration into a YAML file.

Example:

```yaml
services:
  - name: users-service
    url: http://users-api

routes:
  - name: users-route
    paths:
      - /users
```

---

### Step 2: Edit the YAML

You can manually modify the configuration file.

Example:

```yaml
services:
  - name: payment-service
    url: http://payment-api:8080
```

---

### Step 3: Sync Changes to Kong

```bash
deck sync
```

decK compares:

- current Kong configuration
- YAML configuration

Then updates Kong to match the YAML file.

---

## What is Drift Detection?

Suppose your YAML contains:

```yaml
rate_limit: 100
```

But someone manually changes Kong production settings to:

```text
rate_limit: 1000
```

decK can detect this mismatch.

This is called:

> Configuration Drift

Useful for DevOps and production stability.

## Why decK is Useful

Without decK:

- Manual changes in UI
- Hard to track updates
- No version control
- Easy to make mistakes

With decK:

```text
Git Repository
      |
      v
kong.yaml
      |
      v
deck sync
      |
      v
Kong Gateway
```

Benefits:

- Version controlled
- Reproducible
- Easy rollback
- CI/CD friendly
- Automated deployments

## Installation

### Linux

```bash
curl -sL https://github.com/kong/deck/releases/download/v1.37.0/deck_1.37.0_linux_amd64.tar.gz -o deck.tar.gz

tar -xf deck.tar.gz -C /tmp

sudo cp /tmp/deck /usr/local/bin/
```

### Docker

```bash
docker pull kong/deck
```

---

## Common decK Commands

| Command | Purpose |
|----------|----------|
| `deck dump` | Export Kong configuration |
| `deck sync` | Apply YAML config to Kong |
| `deck diff` | Show differences |
| `deck validate` | Validate YAML file |
| `deck reset` | Delete all Kong entities |

---

## One-Line Summary

```text
Kong runs APIs.
YAML defines the desired configuration.
decK syncs that configuration into Kong.
```
